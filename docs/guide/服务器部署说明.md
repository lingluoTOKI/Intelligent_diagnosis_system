# 服务器部署说明

面向阿里云轻量服务器（Ubuntu 22.04，2 核 / 2GB 内存 / 40GB 盘）的部署说明。
访问入口：`http://game.lingluotoki.dpdns.org:8000`

## 一、为什么服务端不用 PyTorch

2GB 服务器的可用内存有限，PyTorch、模型和并发处理可能造成内存压力；是否发生 OOM 应以
系统日志和实测为准。服务端采用 **ONNX Runtime** 加载 `models/server/best512.onnx`，
减少依赖和运行开销。常驻内存、安装体积需要按实际部署记录填写，不能作为固定数值承诺。

服务端不安装、也不导入：PyTorch、Ultralytics、PyQt5。`src/core` 的历史与问答模块
（history / llm / reference_advice）是纯标准库加 requests，可以正常复用。

## 二、必须知道的三个事实

1. **实际输入尺寸是 512，不是 224。**
   权重 `best.pt` 内部自带 `Resize(512) + CenterCrop(512)` 的预处理，Ultralytics 优先使用它，
   会忽略传入的 `imgsz` 参数。实测对同一张图传 224 与 512 结果完全相同。
   `configs/app_config.json` 里的 `image_size: 224` 实际未生效。
   因此服务端必须使用 512 输入的 ONNX，即 `best512.onnx`；仓库里那份 512 的 `best.onnx` 是对的。
   这一点写报告时要按 512 写，不要写 224。

2. **不要按 224 重新导出 ONNX。**
   用 224 导出的权重与桌面端结果不一致（实测 20 张样本里只有 5 张 Top-1 相同）。
   需要重新导出时用 `scripts/export_onnx.py`，它会自动采用权重自带尺寸。

3. **导出脚本会覆盖原位置的 best.onnx。**
   导出后请确认 `models/custom/AKConv_best_moudle/best.onnx` 仍然存在；
   若被覆盖，用 `git checkout -- models/custom/AKConv_best_moudle/best.onnx` 恢复。

```bash

```

| 接口 | 说明 |
|---|---|

### 批量批次号（2026-10-13 追加）

一次「开始分类」生成一个可读批次号，形如 `B20261013-200114-4dc9`（`B` + 日期时间 + 4 位随机后缀）：

- 写入 `records.batch_id`，同时登记到 `batches` 表（`planned` 登记张数）与 `batch_items` 表（逐项结果）
- 历史记录页可按批次号筛选；表格「时间 / 批次」列中的批次标签可点击，直接跳到历史页按该批次查看
- 批量页「查看近期批次…」下拉列出最近批次，选中后自动跳转并填入筛选
- 失败项不写 `records`，因此 `planned` 与 `saved` 的差值即失败或跳过的张数
- 「重试失败项」属于新一次提交，会生成新的批次号

### DeepSeek 在线问答（DEEPSEEK_API_KEY）

服务端**支持** DeepSeek 对话，但默认未配置密钥。两种接口的表现不同，容易误解：

| 场景 | 已配置密钥 | 未配置密钥 |
|---|---|---|
| 分类后「生成辅助建议」（`/api/chat` 带 `disease`） | DeepSeek 在线回答，`source: deepseek` | 返回本地静态参考，开头标注「来源：local-reference」 |
| 「多轮问答」自由提问（`/api/chat` 带 `question`） | DeepSeek 在线回答 | **返回失败**：「未配置 DEEPSEEK_API_KEY，在线问答不可用」 |

也就是说：未配置密钥时，**辅助建议还能出本地参考内容，但多轮问答会直接提示不可用**——
这是有意设计，不伪造在线结果。

「已配置密钥」包含两种方式，效果完全等价：

**方式一：服务端环境变量（推荐用于固定部署）**

在 systemd 单元里写入 `DEEPSEEK_API_KEY`：

```bash
sudo sed -i 's#^Environment="DEEPSEEK_API_KEY=.*"#Environment="DEEPSEEK_API_KEY=sk-你的密钥"#' \
  /etc/systemd/system/eye-diagnosis.service
sudo systemctl daemon-reload && sudo systemctl restart eye-diagnosis
```

若该行不存在，直接编辑服务文件，在 `[Service]` 段加一行 `Environment="DEEPSEEK_API_KEY=sk-你的密钥"`。

**方式二：浏览器设置页（适合临时演示、不想改服务器文件）**

打开网页端「系统设置」页，找到「DeepSeek 在线问答」卡片，在 API Key 输入框填入以 `sk-` 开头的密钥，点「保存并启用」即可。
密钥**只保存在当前浏览器（localStorage），不上传到除 DeepSeek 以外的任何服务器**；每次打开页面会自动重新下发到服务端内存。
服务端重启后若未配置环境变量，需要本机浏览器再提交一次（打开设置页即自动完成）。

两种方式配置是否生效，都可在设置页的「在线问答」一行确认：显示「已配置」即为生效。
其他参数：端点 `https://api.deepseek.com/v1/chat/completions`，模型 `deepseek-chat`，
连接/读取超时 5s / 30s，失败重试 2 次，保留最近 6 轮对话上下文。

### 访问口令（EYE_ACCESS_CODE）

服务支持一个可选的**访问口令**。设置后：

- 未验证的访问者打开页面会看到登录页（`src/server/static/login.html`），直接调 `/api/*` 返回 401
- 口令正确后写入 `eye_access` Cookie（**HttpOnly**，有效期 7 天），之后免输
- Cookie 中保存的是由口令派生的 HMAC 值，**不含明文口令**
- 连续输错 10 次会在 60 秒内冷却，防暴力试口令
- 不设置该环境变量则**完全关闭口令校验**（本机开发默认关闭，不影响现有部署）

在服务器上启用（以 `eye2026` 为例，请自行改成更强的口令）：

```bash
sudo sed -i 's#^Environment="DEEPSEEK_API_KEY=.*"#Environment="DEEPSEEK_API_KEY="\nEnvironment="EYE_ACCESS_CODE=eye2026"#' \
  /etc/systemd/system/eye-diagnosis.service
sudo systemctl daemon-reload && sudo systemctl restart eye-diagnosis
```

若该行不存在，直接编辑服务文件，在 `[Service]` 段加一行 `Environment="EYE_ACCESS_CODE=eye2026"`。

新增接口：`POST /api/login`、`POST /api/logout`、`GET /api/access`（前端用它判断是否需要口令，
不泄露口令本身）。页面右上角在启用口令时会显示「退出」按钮。

## 十二、已知限制

- 服务器无 GPU，单图推理约 200 毫秒，比本机（53 毫秒）慢约 4 倍，报告应使用服务器实测值。
- 未配置 `DEEPSEEK_API_KEY` 时，辅助说明接口返回本地静态参考并在响应中标注来源，不伪造在线结果；
  多轮问答直接返回不可用提示。配置方法见上文「DeepSeek 在线问答」小节。
- SQLite 适合单人演示，多用户并发写入需另行评估。
- 网页端的**本机摄像头**依赖浏览器的 `getUserMedia`，要求 HTTPS 或 localhost；
  域名已启用 HTTPS 时可直接使用，否则浏览器会拒绝打开摄像头。
- 网页端的**开发板摄像头**占位保留但不接流：开发板经局域网 UDP 5002 推流，
  公网浏览器无法直接接收局域网内硬件的视频流，该硬件演示请用桌面客户端。
- 网页端的**语音输入**由浏览器本机完成，需 Chromium 内核浏览器且要求 HTTPS。
- **语音朗读**优先由服务端通过 `edge-tts` 生成晓晓自然音色 MP3，相同文本、语言和语速使用缓存；
  首次生成受网络影响，失败时自动降级到浏览器本机语音。音频在页面内播放，不弹出外部播放器。
- 界面字号、阅读字号与语音参数保存在浏览器 localStorage，不上传服务器，换设备需重新设置。
- 批量分类在服务端串行执行，2 核 CPU 下约 200 毫秒/张；一次最多 100 张，超出返回 413。
  失败项如实标注状态，不写历史，也不会生成占位结果。
- 历史导出一次最多 200 条（受接口 `limit` 上限约束）。
- 页面与接口仅用于课程演示，输出结果不构成医学诊断依据。
