## 当前事实基线

原始机器可读证据位于 `docs/evidence/course_evidence_audit.json`，可使用下列命令复查。该命令读取图像、检查点与服务健康接口，不调用在线问答、不写分类历史、不修改数据集。
四组 CSV、运行清单和参数文件的归档副本位于 `docs/evidence/experiments/`；已有报告图归档于 `docs/evidence/report_figures/`，不随 `runs/` 被忽略。源实验检查点仍保留在本机 `runs/`，没有删除或移动。

```powershell
python scripts/audit_course_evidence.py --model-structures
```

- 数据目录：训练集 5110 张，验证集 1163 张；跨集合存在 140 个完全相同的内容哈希。哈希检测不等于患者 ID 检查，也不包括所有近似重复图像。
- 当前部署 PyTorch 检查点：参数量 **1,448,536**，AKConv 层数 **0**，内置 `Resize(512) + CenterCrop(512)`。
- 历史对比基线：参数量 **1,541,352**，AKConv 层数 **0**，内置 224 预处理。
- 历史 AKConv 候选：参数量 **1,487,772**，AKConv 层数 **6**，内置 224 预处理。
- 四组实验 CSV 各有 50 轮；各自存在原始日志和检查点。用户已完成这些实验，本轮不触发重训。
- 对比检查点在相同本地加载器中逐层核对：两套框架的基线结构与张量哈希相同，两套框架的 AKConv 候选也相同。这不能作为四种不同网络架构的性能比较；也不能仅由哈希相同断定日志被复制。
- 两份部署 ONNX 的文件内容哈希相同，部署推理与候选实验设置应分开讨论。
- 服务器公网 IP 和域名的 `/api/health` 最终直接连接复查均返回 HTTP 200、512 输入、CPUExecutionProvider、历史库可用。中间超时发生在本机 `127.0.0.1:7897` 代理链路；仅针对健康请求关闭环境代理后恢复，未修改全局代理配置，不能据此判定服务器故障。各次状态保留在证据 JSON 中。健康检查通过不能替代网页功能端到端验收。

## 报告事实纠错

1. 原 ODIR 引文的 `arXiv:2004.11419` 实为另一篇语音研究，已替换为 [ODIR 官方数据集说明](https://odir2019.grand-challenge.org/dataset/)。公开页面并不能证明本地数据的原始标签转换与患者划分。
2. 原 AKConv 引文的作者与 `arXiv:2309.13855` 错误，已按原始论文更正为 [Xin Zhang 等，arXiv:2311.11587v2](https://arxiv.org/abs/2311.11587v2)。
3. 眼科综述第一作者应为 Ting，已按 [British Journal of Ophthalmology 原始发表页](https://bjo.bmj.com/content/103/2/167) 更正。
4. 同样的数据指纹是对比实验控制变量的正常条件；结构与权重结论已改为依据具体检查点核对。
5. [RETFound 原始研究](https://www.nature.com/articles/s41586-023-06555-x) 已作为后续文献评述的候选依据，不写成本项目已完成的模型实验。
